标题: 调试指南  
描述: 一份关于调试模型上下文协议(MCP)集成的全面指南  

在开发MCP服务器或将其与应用程序集成时，有效的调试至关重要。本指南将介绍MCP生态系统中可用的调试工具和方法。  

<Info>  

本指南适用于macOS平台。其他平台的指南即将推出。  

</Info>  

## 调试工具概览  

MCP提供了多层次的调试工具：  

1. **MCP检查器**  
   - 交互式调试界面  
   - 直接测试服务器  
   - 详见[检查器指南](/legacy/tools/inspector)  

2. **Claude桌面开发者工具**  
   - 集成测试功能  
   - 日志收集系统  
   - 支持Chrome开发者工具集成  

3. **服务器日志**  
   - 自定义日志实现  
   - 错误追踪功能  
   - 性能监控模块  

## 在Claude桌面中调试  

### 检查服务器状态  

通过Claude.app界面可查看基础服务器信息：  

1. 点击<img src="/images/claude-desktop-mcp-plug-icon.svg" style={{display: 'inline', margin: 0, height: '1.3em'}} />图标可查看：  
   - 已连接的服务器  
   - 可用提示词和资源  

2. 点击"搜索与工具"<img src="/images/claude-desktop-mcp-slider.svg" style={{display: 'inline', margin: 0, height: '1.3em'}} />图标可查看：  
   - 模型可使用的工具集  

### 查看日志  

实时追踪Claude桌面的MCP日志：  

```bash  
# 实时跟踪日志  
tail -n 20 -F ~/Library/Logs/Claude/mcp*.log  
```  

日志内容包含：  

- 服务器连接事件  
- 配置问题记录  
- 运行时错误  
- 消息交换详情  

### 使用Chrome开发者工具  

在Claude桌面中调用Chrome开发者工具排查客户端问题：  

1. 创建包含`allowDevTools`设置的配置文件：  

```bash  
echo '{"allowDevTools": true}' > ~/Library/Application\ Support/Claude/developer_settings.json  
```  

2. 使用快捷键`Command-Option-Shift-i`打开开发者工具  

注意：将出现两个开发者工具窗口：  

- 主内容窗口  
- 应用标题栏窗口  

通过控制台面板检查客户端错误，通过网络面板分析：  

- 消息载荷  
- 连接时序  

## 常见问题  

### 工作目录问题  

在Claude桌面中使用MCP服务器时需注意：  

- 通过`claude_desktop_config.json`启动的服务器工作目录可能未定义（如macOS下的`/`目录）  
- 配置文件和`.env`中应始终使用绝对路径确保可靠性  
- 命令行直接测试时，工作目录为执行命令的位置  

例如在配置文件中应使用：  

```json  
{  
  "command": "npx",  
  "args": [  
    "-y",  
    "@modelcontextprotocol/server-filesystem",  
    "/Users/用户名/data"  
  ]  
}  
```  

而非相对路径如`./data`  

### 环境变量  

MCP服务器默认仅继承部分环境变量（如`USER`、`HOME`和`PATH`）。  

如需自定义变量，可在配置文件中添加`env`字段：  

```json  
{  
  "myserver": {  
    "command": "mcp-server-myapp",  
    "env": {  
      "MYAPP_API_KEY": "密钥值"  
    }  
  }  
}  
```  

### 服务器初始化  

常见初始化问题包括：  

1. **路径问题**  
   - 错误的可执行文件路径  
   - 缺失必要文件  
   - 权限问题  
   - 建议使用绝对路径  

2. **配置错误**  
   - JSON语法错误  
   - 缺少必填字段  
   - 类型不匹配  

3. **环境问题**  
   - 缺失环境变量  
   - 变量值错误  
   - 权限限制  

### 连接问题  

服务器连接失败时建议：  

1. 检查桌面端日志  
2. 确认服务进程运行状态  
3. 使用[检查器](/legacy/tools/inspector)独立测试  
4. 验证协议兼容性
## 实现日志记录

### 服务器端日志记录

当构建使用本地标准输入输出[传输](/legacy/concepts/transports)的服务器时，所有输出到stderr（标准错误）的日志消息都会被宿主应用程序（如Claude Desktop）自动捕获。

<Warning>

本地MCP服务器不应将日志消息输出到stdout（标准输出），这会干扰协议运行。

</Warning>

对于所有[传输方式](/legacy/concepts/transports)，您也可以通过发送日志消息通知向客户端提供日志：

<CodeGroup>

```python Python
server.request_context.session.send_log_message(
  level="info",
  data="服务器启动成功",
)
```

```typescript TypeScript
server.sendLoggingMessage({
  level: "info",
  data: "服务器启动成功",
});
```

</CodeGroup>

需要记录的重要事件：

- 初始化步骤
- 资源访问
- 工具执行
- 错误情况
- 性能指标

### 客户端日志记录

在客户端应用中：

1. 启用调试日志
2. 监控网络流量
3. 跟踪消息交换
4. 记录错误状态

## 调试工作流

### 开发周期

1. 初始开发
   - 使用[检查器](/legacy/tools/inspector)进行基本测试
   - 实现核心功能
   - 添加日志点

2. 集成测试
   - 在Claude Desktop中测试
   - 监控日志
   - 检查错误处理

### 测试变更

高效测试变更的方法：

- **配置变更**：重启Claude Desktop
- **服务器代码变更**：使用Command-R重新加载
- **快速迭代**：开发过程中使用[检查器](/legacy/tools/inspector)

## 最佳实践

### 日志策略

1. **结构化日志**
   - 使用统一格式
   - 包含上下文
   - 添加时间戳
   - 跟踪请求ID

2. **错误处理**
   - 记录堆栈追踪
   - 包含错误上下文
   - 跟踪错误模式
   - 监控恢复情况

3. **性能追踪**
   - 记录操作耗时
   - 监控资源使用
   - 跟踪消息大小
   - 测量延迟

### 安全考量

调试时需注意：

1. **敏感数据**
   - 清理日志内容
   - 保护凭据信息
   - 脱敏个人信息

2. **访问控制**
   - 验证权限
   - 检查认证状态
   - 监控访问模式

## 获取帮助

   - 验证环境

2. **支持渠道**
   - GitHub issues
   - GitHub discussions

3. **提供信息**
   - 日志片段
   - 配置文件
   - 重现步骤
