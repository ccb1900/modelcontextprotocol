---
title: "根路径"
description: "理解MCP中的根路径概念"
---

根路径是MCP中定义服务器操作边界的核心概念。它让客户端能够向服务器指明相关资源及其位置。

## 什么是根路径？

根路径是客户端建议服务器应关注的URI地址。当客户端连接服务器时，会声明服务器应处理的根路径集合。虽然主要用于文件系统路径，但根路径可以是任何有效的URI，包括HTTP网址。

例如，根路径可以是：

```
file:///home/user/projects/myapp
https://api.example.com/v1
```

## 为什么需要根路径？

根路径具有以下重要作用：

1. **引导性**：向服务器指明相关资源位置
2. **明确性**：清晰界定工作空间包含的资源范围
3. **组织性**：通过多根路径同时处理不同资源

## 工作原理

支持根路径的客户端会：

1. 在连接时声明`roots`能力
2. 向服务器提供建议的根路径列表
3. 在根路径变更时通知服务器（如支持该功能）

虽然根路径是建议性而非强制性的，但服务器应当：

1. 尊重客户端提供的根路径
2. 使用根URI定位和访问资源
3. 优先处理根路径边界内的操作

## 典型应用场景

根路径常用于定义：

- 项目目录
- 代码仓库位置
- API端点
- 配置文件位置
- 资源边界

## 最佳实践

使用根路径时建议：

1. 仅提供必要的资源路径
2. 使用清晰易懂的命名
3. 监控根路径可访问性
4. 优雅处理路径变更

## 示例

以下是MCP客户端暴露根路径的典型配置：

```json
{
  "roots": [
    {
      "uri": "file:///home/user/projects/frontend",
      "name": "前端代码库"
    },
    {
      "uri": "https://api.example.com/v1",
      "name": "API接入点"
    }
  ]
}
```

该配置建议服务器同时关注本地代码库和API端点，并保持逻辑隔离。
