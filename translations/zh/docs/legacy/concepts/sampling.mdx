---  
标题: "采样功能"  
描述: "让您的服务器能够向大语言模型请求补全内容"  

采样是MCP的一项强大功能，它允许服务器通过客户端向大语言模型(LLM)请求补全内容，在确保安全与隐私的前提下实现复杂的智能代理行为。  

<Info>  

MCP的此功能目前尚未在Claude桌面客户端中支持。  

</Info>  

## 工作原理  
采样流程包含以下步骤：  

1. 服务器向客户端发送`sampling/createMessage`请求  
2. 客户端审核并可能修改请求内容  
3. 客户端向LLM发起采样请求  
4. 客户端审核返回的补全内容  
5. 客户端将最终结果返回给服务器  

这种人机协同设计确保用户始终掌控LLM接收和生成的内容。  

## 消息格式  
采样请求采用标准化消息格式：  

```typescript  
{  
  messages: [  
    {  
      role: "user" | "assistant",  
      content: {  
        type: "text" | "image",  

        // 文本内容:  
        text?: string,  

        // 图片内容:  
        data?: string,             // base64编码  
        mimeType?: string  
      }  
    }  
  ],  
  modelPreferences?: {  
    hints?: [{  
      name?: string                // 建议的模型名称/系列  
    }],  
    costPriority?: number,         // 0-1，成本优化权重  
    speedPriority?: number,        // 0-1，响应速度权重  
    intelligencePriority?: number  // 0-1，模型能力权重  
  },  
  systemPrompt?: string,  
  includeContext?: "none" | "thisServer" | "allServers",  
  temperature?: number,  
  maxTokens: number,  
  stopSequences?: string[],  
  metadata?: Record<string, unknown>  
}  
```  

## 请求参数详解  

### 消息内容  
`messages`数组包含要发送给LLM的对话历史，每条消息包含：  
- `role`：标识"user"或"assistant"角色  
- `content`：消息内容，可以是：  
  - 文本内容（含`text`字段）  
  - 图片内容（含base64编码的`data`和`mimeType`字段）  

### 模型偏好设置  
`modelPreferences`对象允许服务器指定模型选择偏好：  
- `hints`：模型名称建议数组：  
  - `name`：可匹配完整或部分模型名的字符串（如"claude-3"，"sonnet"）  
  - 客户端可将提示映射到不同提供商的等效模型  
  - 多个提示按优先顺序评估  
- 权重参数（0-1标准化值）：  
  - `costPriority`：控制成本优化优先级  
  - `speedPriority`：控制低延迟响应优先级  
  - `intelligencePriority`：控制高级模型能力优先级  

客户端将根据这些偏好和可用模型最终决定使用的模型。  

### 系统提示  
可选字段`systemPrompt`允许服务器请求特定系统提示，客户端可修改或忽略该内容。  

### 上下文包含  
`includeContext`参数指定MCP上下文的包含范围：  
- `"none"`：不添加额外上下文  
- `"thisServer"`：包含当前请求服务器的上下文  
- `"allServers"`：包含所有连接MCP服务器的上下文  

实际包含内容由客户端控制。  

### 采样参数  
可通过以下参数微调LLM采样：  
- `temperature`：控制随机性（0.0到1.0）  
- `maxTokens`：控制生成的最大token数  
- `stopSequences`：终止生成的序列数组  
- `metadata`：提供商特定的扩展参数  

## 响应格式  
客户端返回的补全结果格式：  

```typescript  
{  
  model: string,  // 实际使用的模型名称  
  stopReason?: "endTurn" | "stopSequence" | "maxTokens" | string,  
  role: "user" | "assistant",  
  content: {  
    type: "text" | "image",  
    text?: string,  
    data?: string,  
    mimeType?: string  
  }  
}  
```
## 示例请求

以下是一个向客户端请求采样的示例：

```json
{
  "method": "sampling/createMessage",
  "params": {
    "messages": [
      {
        "role": "user",
        "content": {
          "type": "text",
          "text": "当前目录下有哪些文件？"
        }
      }
    ],
    "systemPrompt": "你是一个得力的文件系统助手",
    "includeContext": "thisServer",
    "maxTokens": 100
  }
}
```

## 最佳实践

实现采样功能时应注意：

1. 始终提供清晰、结构化的提示
2. 正确处理文本和图像内容
3. 设置合理的令牌限制
4. 通过`includeContext`包含相关上下文
5. 使用前验证响应内容
6. 优雅地处理错误
7. 考虑对采样请求进行速率限制
8. 记录预期的采样行为
9. 使用不同模型参数进行测试
10. 监控采样成本

## 人工监督机制

采样功能设计考虑了人工监督：

### 对于提示

- 客户端应向用户展示拟定的提示
- 用户应能修改或拒绝提示
- 系统提示可以被过滤或修改
- 上下文包含由客户端控制

### 对于生成结果

- 客户端应向用户展示生成内容
- 用户应能修改或拒绝生成结果
- 客户端可以过滤或修改生成内容
- 用户控制使用哪个模型

## 安全注意事项

实现采样功能时需注意：

- 验证所有消息内容
- 清理敏感信息
- 实施适当的速率限制
- 监控采样使用情况
- 传输数据加密
- 处理用户数据隐私
- 审计采样请求
- 控制成本风险
- 设置超时机制
- 优雅处理模型错误

## 常见模式

### 代理工作流

采样支持以下代理模式：

- 读取和分析资源
- 基于上下文做出决策
- 生成结构化数据
- 处理多步骤任务
- 提供交互式协助

### 上下文管理

上下文管理的最佳实践：

- 只请求必要的最小上下文
- 清晰组织上下文结构
- 处理上下文大小限制
- 按需更新上下文
- 清理过期上下文

### 错误处理

健壮的错误处理应：

- 捕获采样失败
- 处理超时错误
- 管理速率限制
- 验证响应内容
- 提供备用行为
- 适当记录错误

## 局限性

请注意以下限制：

- 采样依赖客户端能力
- 用户控制采样行为
- 上下文大小有限制
- 可能适用速率限制
- 需要考虑成本因素
- 模型可用性不同
- 响应时间各异
- 并非所有内容类型都受支持
